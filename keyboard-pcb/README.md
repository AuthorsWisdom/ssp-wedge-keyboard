# Seven Swords Wedge — keyboard PCB (KB-P1)

An original 2-layer, 240 × 102 mm, 1.6 mm board: RP2040 + W25Q128 flash, USB-C (USB 2.0 device, 5.1 kΩ CC pull-downs, USBLC6-2 ESD), AMS1117-3.3, 48 MX hot-swap keys (4 × 12, COL2ROW, 1N4148W per key), and an EC11E15244G1 encoder with push. The RP2040 core follows the Raspberry Pi "Minimal RP2040" reference design (MIT, see NOTICE.md). Nothing here comes from Micro Journal.

**Status: design only.** Nothing has been ordered, fabbed, or uploaded, and nothing is tested on hardware.

## Pin map (matches firmware/rmk-wedge/keyboard.toml)
| Signal | GPIO |
|---|---|
| COL0–COL11 | GPIO0–GPIO11 |
| ROW0–ROW3 | GPIO12–GPIO15 |
| ROW4 (encoder push only, key (4,11) via D49) | GPIO18 |
| ENC_A / ENC_B | GPIO16 / GPIO17 |
| Free | GPIO19–GPIO29 (unconnected pads) |

SW49 is BOOTSEL and SW50 is RUN/reset. In the Wedge case they're reached with a SIM-eject pin through the two Ø3 poke holes in the case plate, over PCB (86, 94) = BOOT and (86, 85) = RESET. To flash: hold BOOT, tap RESET, release BOOT, and the `RPI-RP2` drive mounts over the internal cable. You don't need to open the case.

**J2 (3-pin SWD: SWCLK / SWDIO / GND) is DNP. Do not fit it.** A fitted header collides with the case plate (Wedge case v1.1). It's marked DNP on the board and in the schematic, it's left out of `bom-jlc.csv` and `cpl-jlc.csv`, and it's listed in `fab/dnp.csv` and `fab/hand-solder.csv` as DO NOT FIT. If SWD is ever needed, use pogo pins on the bare pads with the board out of the case.

## Regenerate
The whole board is generated by scripts. Don't hand-edit the board, because the next run overwrites it.
```
cd gen
python3 gen_sch.py          # schematic from design.py (+ ERC / netlist)
python3 check_netlist.py    # schematic vs design.py: expect "mismatches: 0"
python3 gen_pcb.py          # placement, outline, holes, netclasses
python3 route.py dsn        # export Specctra DSN
python3 route.py route      # run Freerouting (about 10 to 20 min)
python3 route.py ses        # import the SES, clamp sub-0.15 mm stubs to 0.15, refill zones
cd .. && kicad-cli pcb drc --schematic-parity -o reports/drc.rpt ssp-wedge-kb.kicad_pcb
cd gen && python3 fab.py    # gerbers, drill, BOM/CPL, hand-solder list, renders, DXF
```
Requirements: KiCad 9.0.x (kicad-cli + pcbnew Python) and Freerouting 2.5.0. If you only change placement or the schematic, re-run gen_pcb and then `route.py ses` with the existing .ses to get the same routing back.

## Routing and DRC
- Freerouting reached **0 unrouted, 0 violations**: 1,026 track segments and 127 vias. There's a GND pour on both layers.
- Netclasses:
  - Power (VBUS/GND): 0.25 mm track, 0.6 mm via
  - Rail (+3V3/+1V1): 0.2 mm track, 0.6 mm via
  - Default: 0.2 mm track, 0.5/0.3 mm via
  - Clearance is 0.15 mm for all classes. Everything is within JLC's standard 2-layer capability (0.127 mm track and space, 0.3 mm drill).
- DRC with schematic parity: **0 errors, 0 unconnected.** The remaining warnings are expected:
  - 2 × silk_edge_clearance: the USB-C connector's own silk runs past the board edge where the mouth overhangs. JLC clips it.
  - 15 × net_conflict (parity warnings):
    - 2 for the EC11 mounting lugs, which are tied to GND on the PCB and have no schematic pin
    - 13 for no-connect pins (J1 SBU1/SBU2 and the unused RP2040 GPIO19–29), which have no copper
- `ssp-wedge-kb.kicad_dru` accepts one thermal spoke on the GND pads of two 0402 decoupling caps (C4, C6). They're boxed in by QFN fan-out tracks.
